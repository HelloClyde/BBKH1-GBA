本版将退出键（Escape）保留给游戏，允许在暂停菜单中绑定，未绑定时不退出、不暂停；
退出键也不作为暂停菜单的返回/取消键。触摸和 P 继续负责暂停。
固件将退出/返回两键合并为原生键码 1，包装器使用事件身份区分；返回退出必须来自
明确的返回键事件，不能由原生查询或过期的别名状态猜测。

保留 SDK `067fe072`、gpSP `69e86ebe`、gnuboy `c367bb4b` 的固定版本，未升级核心。
使用 GNU MIPS GCC 15.2.0 和 requirements.txt 的固定依赖构建；BDA 日期固定为
2026-10-15 以保持可复现。tag 工作流从干净检出构建，核对上述确切 BDA 和运行记录，
所有主机/MIPS 回归通过后才生成 Release。

## MIPS 回归

主机按键测试覆盖退出键可绑定、按住/松开、与返回共用键码、两次采样间漏掉释放、
过期别名不得退出，以及原有组合键。普通 BDA 的 GBA/GB/GBC 暂停菜单回归实际
绑定退出键为 A，继续游戏后按住再松开，并验证继续运行、存档/读档、配置重载。
音量回归覆盖 5% 步长、0/100 边界、配置兼容和退出恢复。

见 [暂停菜单回归](evidence/v0.12.6-menu.json) 和 [音量回归](evidence/v0.12.6-volume.json)。
这些测试使用 Unicorn 执行真实 MIPS 二进制，固件服务由替身提供，不是真机性能测试。

## 完整 H1 固件模拟器

两份确切 BDA 分别在专用私有 NAND、完整 V1.41 固件和 QEMU `bbkh1` 中运行，
从原生文件选择器进入，不修改原始设备 dump，不替换固件服务。
`tools/test_h1_escape_native.py` 通过真实按键/触摸操作 UI，只读检查调试内存：

- 三核心在未绑定退出键时继续运行，退出/暂停标志保持为 0。
- 实际在按键映射 UI 中将退出键绑定为 A，并记录实际帧缓冲。
- 按住退出键时 GBA KEYINPUT 的 A 位拉低，释放后恢复；GB/GBC 测试卡带 RAM
  的 A 状态由 `0x11` 变为 `0xA5` 再恢复，游戏帧数持续推进。
- 暂停菜单中的退出键不会关闭菜单；触摸和 P 仍可暂停，继续后帧数推进。
- 更换游戏恢复原系统音量；重新打开 GBA 后退出键绑定仍存在。
- 最后通过暂停菜单“退出游戏”回到桌面，日志正常结束；四次游戏退出的图像错误
  均为 0，NAND 无不完整提交记录，诊断版性能计时 fault 为 0。

完整结果见 [普通版](evidence/v0.12.6-native-normal.json) 和
[诊断版](evidence/v0.12.6-native-profile.json)。本版按键绑定截图来自普通版真实帧缓冲，
原有截图保留各自版本和用户来源，不能作为本版运行证据。

本次确切构建尚未在真机复测。模拟器结果不代表商业游戏或真机 FPS，其他固件未验证。
固件、NAND、测试 ROM、原始音频及个人存档不随源码或 Release 分发。
