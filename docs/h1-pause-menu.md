# H1 触摸暂停菜单（v0.11）

游戏中点击屏幕任意位置，或按 P，暂停并显示中文设置菜单。打开菜单的第一次触摸松开不会触发菜单按钮；再次点击按钮并在同一按钮内松开才执行，滑出按钮会取消。方向键移动选择，确认／回车／Z 执行，返回／Escape／P 返回上一级；主菜单中返回即继续游戏。

暂停期间不调用核心的 run，停止计时器、取消 PCM 播放并清空音频环形缓冲；继续时重新预缓冲、重设计时基准和释放残留游戏按键。GBA 的日历时钟继续按 H1 实际时间推进。

v0.11 保留已打开的 PCM 设备和描述符，继续时复用，不再每次销毁和完整初始化。V1.41 的 AIC DMA 在暂停时可能继续输出全零样本，游戏声音和核心运行均停止；关闭声音、换 ROM 和退出时释放设备。耗时对照和优化方向见 [性能分析](h1-performance.md)。

## 按键、显示与声音

按键映射支持十字键、A、B、L、R、START、SELECT。选中游戏按键后按实体键即可绑定；同一个实体键只对应一个游戏按键。被替换的旧映射显示“未设置”，可以重新分配。默认 A 的 Z 和确认两个别名，在重新绑定 A 时一起移除。GB/GBC 忽略 L/R。

P、M、V、F、Escape、返回和电源保留为系统／前端功能，不能绑定。选择“恢复默认按键”恢复出厂映射。菜单导航始终使用实体方向键和确认，不受游戏映射影响。

显示可循环切换原始大小、保持比例、480×272 全屏拉伸、保持比例线性平滑；拉伸会改变宽高比。跳帧支持 0、1、2，不改变游戏逻辑速度。声音可开关。v0.12.3 用 MXU1 优化线性插值，实际速度还取决于场景。

配置按 ROM 独立保存在 `game.gba.cfg.s0/.s1`（GB/GBC 同理），只在变化时写入。损坏或不兼容的配置保留原文件并使用默认值，本次禁用写入。

## 即时存档与读档

提供三个槽位，操作后仍停留在暂停菜单，按返回再继续。保存当前槽位会更新该槽位；读取空槽、损坏槽或不兼容的格式会显示消息。

文件放在 ROM 旁边，例如槽位 1 为 `game.gba.st1.s0/.s1`，槽位 2/3 使用 `.st2`/`.st3`。每个槽位仍采用 A/B 两份、代数、ROM 身份、CRC、关闭后回读验证。备份时应保留两份。最新一份损坏会尝试上一份；两份都坏时保留文件并拒绝写入。

这与原来的 `game.gba.s0/.s1` **电池存档**不同：即时存档保存 CPU、工作内存、图形、声音、卡带内存和时钟状态，可以恢复到运行位置。启动时仍只自动恢复电池存档，需要手动选择即时读档。

GBA 使用固定版本 gpSP 的序列化接口，并补上卡带 SRAM 和 H1 RTC 状态，读档后刷新 JIT 缓存。GB/GBC 使用本项目版本 1 的快照格式，保存无指针的机器状态并重建内存映射、图块及调色板缓存。即时存档不承诺与其他模拟器或未来核心版本兼容。

## H1 接口

V1.41 队列事件 11 为触摸按下、12 为移动、8 为松开，事件值不包含屏幕坐标。`GUI+0x6C0` 的函数签名为 `void (uint16_t *x, uint16_t *y)`，读取 ADC 并应用系统触摸校准，返回 480×272 LCD 坐标。

完整固件的原生游戏窗口不自动刷新缓存的坐标，因此不能只读取缓存值。平台封装验证该函数的已研究指令形状后调用导出接口，未识别的固件不调用未知函数；仍可用 P 和实体键操作菜单。该适配在项目平台层完成，没有改写 SDK 或第三方核心子模块。
