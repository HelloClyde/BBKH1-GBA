# H1 系统文件选择器调用依据

来源：用户提供的 `BB虚拟机.bda`（94,976 字节）。
SHA-256：`f6b8c3e6df8c74b6786f1018d37610b1d6afb205e0ad8cdd07b75409ad517dac`。
原程序未加入项目源码，也未改写原文件。

H1 加载入口 `0x83C00020`，BDA payload 偏移 `0x785C`。初始化代码从
`0x83C00004` 读取 GUI 服务表并保存在 `0x83C0FAC4`。
主函数 `0x83C01620` 存在两条文件选择路径：

| 调用地址 | 条件 | 参数 |
| --- | --- | --- |
| `0x83C016F0` | wallpaper.lib 打开成功，先显示背景 | a0 = `A:\BBasic\`；a1 = `bin`；a2 = sp+64 |
| `0x83C01814` | wallpaper.lib 打开失败，直接选择 | 同上 |

两处均从 GUI 表加载 `+0x9EC` 的函数指针，然后使用 `jalr` 调用。
主函数栈帧为 360 字节，输出路径位于 sp+64，下一独立局部变量位于 sp+328，
因此原调用者为输出路径预留了 264 字节。API 没有传入缓冲区长度。
程序随后把路径复制给打开 BIN 文件的流程，未拼接默认目录。

可复现跟踪：

```powershell
python tests/trace_bbvm_selector.py "F:\应用\程序\BB虚拟机.bda"
```

此测试在 Unicorn 中执行原程序初始化和主函数，截获 RES 日志、背景打开和文件选择
服务，观察到实际参数 `A:\BBasic\`、`bin`、sp+64；背景打开替身返回 0，因此走
`0x83C01814`。输出证据位于 `build/verification/bbvm-selector-trace.json`。

项目封装：`src/platform/file_selector.c`。按上述 ABI 调用：

```c
/* GUI table from slot 0x83C00004, byte offset 0x9EC */
function(initial_directory, "gba;gb;gbc", output_path);
```

原程序忽略 v0，故本项目也不猜测原函数的返回类型或成功返回码。包装器以
初始化后的输出路径判断结果：空路径为取消；绝对路径且扩展名为 `.gba`、`.gb` 或 `.gbc` 时为选中；
无终止符、路径过长或不匹配的扩展名为错误。输出临时区 512 字节，比原调用者预留区大；
选择结果限制为 256 字节（不含 NUL），给 `.s0` / `.s1` 后缀和终止符留出空间。
中文路径按固件返回的 GBK 字节原样传入文件和存档接口，目录提取跳过 GBK 双字节字符，
防止把汉字中的 0x5C 尾字节误认为反斜杠。

v0.4 在完整 V1.41 固件中验证选择器选中文件、中文 GBK 路径和右上角关闭按钮取消。
取消时输出路径为空，包装器返回 0。
V1.41 选择器在取消时也会置游戏显示标志，抑制桌面刷新；只返回应用入口会让
屏幕停在选择器，日志却已写到 `APP_END`。当前取消路径先成对调用
GUI+0x84C / +0x850 恢复桌面显示，再退出，不初始化模拟器核心或音频。
直接调用关闭接口在游戏窗口计数为零时不会恢复该标志，故必须先打开再关闭。
GUI+0x84C / +0x850 分别初始化和关闭原生游戏窗口，现在与每次运行 ROM 成对使用。
选择器返回后固件的游戏显示标志为 1，GUI+0x070 会直接返回，原来的 RGB565
显示路径因此停在文件选择器最后一帧。这不是 gpSP 停止运行：旧版日志仍有连续成功帧。

原生游戏模式改用 GUI+0x8F4：参数为六个 u16 的显示信息输出区和空窗口参数，
返回当前 LCD 帧缓冲指针。V1.41 输出 info[1]=480、info[2]=272、info[3]=1920、
info[5]=32，实际返回 0xA1902000；程序查询指针，不硬编码地址，并检查尺寸、步长和位深。
将 RGB565 转为 0x00RRGGBB 后写入，模拟器显示测试图案和《绿宝石》标题画面。
原有 GUI+0x750 仍能提供 H1 矩阵按下/松开事件，A、Start、M 和 Escape 已实际验证。

此接口保留在项目平台层，没有将候选接口加入 H1 SDK 的已验证公共头文件。
交叉编译和模拟服务表测试覆盖调用参数、取消、中文路径、存档、换 ROM。
完整固件验证覆盖界面、图形生命周期、中文 ROM 加载、存档恢复和退出，
未穷举固件输出路径长度上限。详见 `h1-emulator-test.md`。

v0.7 多格式过滤依据 V1.41 内核解析器 `0x8003C01C`：以 `0x3B`（分号）分隔扩展名，
每项按 11 字节存储并转换为小写，最多 10 项；首字符 `*` 表示全文件。
空字符串的扩展名计数为 0，会隐藏普通文件，不能用来表示不限类型。
传入 `gba;gb;gbc` 后，真实系统选择器按扩展名分组列出三类 ROM，隐藏 `.s0` / `.s1` 和日志。
证据：`build/h1-emulator-test/v07-picker.png`。这些解析器地址仅用于研究，应用仍只调用 GUI 服务表。
