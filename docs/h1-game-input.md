# H1 原生游戏组合按键

v0.12.1 的游戏按键改用固件 **GUI+0x9D8**，原 GUI+0x750 继续负责触摸暂停、系统事件和实体别名辨识。应用不自行访问键盘 GPIO，也不自行屏蔽 IRQ。

## 接口依据

只读检查原 H1 应用，在 BB 虚拟机 `0x83C00DB0`、使命 `0x83C2CFBC/0x83C2CFD4/0x83C2CFF4/0x83C2D014`、雷霆战机 `0x83C01D10` 起的连续调用中发现 GUI 表 `+0x9D8`。使命把多个查询的返回结果合成方向状态位，雷霆战机把多次查询分别存入游戏按键状态。调用签名是 `int query(unsigned native_scancode)`，返回非零表示按住。

V1.41 GUI 表此项指向 `0x80068AE8`，它调用 `0x80008234` 后规范化返回值为 0/1。底层以固件自身键码表查找键位，扫描对应行列并恢复固件扫描状态。上述地址仅用于分析，应用调用运行时 GUI 表，不硬编码固件函数或状态地址。调用清单在 `build/profile-unit/reference-game-input-calls.json`，表定位证据在 `gui-table-address.json`。

这不是原事件队列的 1..42 矩阵编号：例如 D 的事件编号为 10，原生游戏键码为 32；K 的事件编号为 32，原生游戏键码为 37。转换表来自固件自身表。Enter/确认、左右 ALT/对应方向共享游戏键码；借助队列提供的实体身份区分别名，并缓存同一原生键码的查询结果，避免确认键误触 START。

每个核心帧先收取队列事件，再查询已映射的游戏按键与前端快捷键。持有状态独立合成 libretro 位掩码，第二个按键和分别松开不会清空另一键；音频等待循环仅排空事件，不重复查询游戏状态。原设置文件、按键映射、线性缩放和存档格式保持兼容。

## 验证范围

主机测试覆盖 D=右、K=A 的连续按下、两种松开顺序、反向按下顺序、三键、系统伪松开不覆盖查询结果、暂停键只触发一次，以及 Enter/确认分别映射到 START/A。实际交叉编译包和完整 H1 固件组合输入验证结果见 `dist/VERIFICATION.md`。单键队列问题不能推导为 H1 没有组合按键 API；此前自行扫描矩阵的尝试已撤下。

完整 H1 V1.41 普通包测试已通过 GBA/GB/GBC 的实际组合交付，映射通过菜单完成，随后只发送键盘按下/松开并只读核心状态。GBA KEYINPUT 同时接收 A+右，GB/GBC 原创测试卡带的 RAM 同时反映两键。两种按下顺序与独立松开、暂停冻结/继续、换 ROM 和退出均通过。报告 `build/h1-emulator-test/evidence/v121-combo-native.json`，原生日志 `v121-native.log`；本轮没有再次测量真机性能。
